# 局域网共享：共享区 / 浏览器访问

> 像 LocalSend 一样在本机之间收发文字和文件，但**只有一端装 LTools**：其他设备用浏览器
> 打开一条固定地址就能用，不需要装任何客户端。本文记录范围、数据模型、界面、接口与
> 安全边界。**实现若偏离，先改本文再改代码。**

## 0. 目标与边界

**做什么**

- 一个持久的**共享区**：本机发出去的内容记在清单里（**不复制**，大文件秒加），
  对方发来的落 `share/inbox/`。
- 一条**固定**的共享地址 + 二维码：默认 `http://<ip>:<端口>/`，启用令牌后是
  `/s/<令牌>`；重启、关窗、重开都不变。
- 浏览器端一屏**双向流**：上面是电脑发来的，下面是你发去的，底部常驻发送条。
  PC / 平板 / 手机通用。
- 服务可开可关，记住上次状态；关掉窗口不影响共享，托盘里能看状态。

**不做什么**

- **不做「两端都装」的发现与配对**：没有多播、没有设备列表、没有「选接收方」。
  地址就是唯一的接收方，浏览器打开即用。
- **不做短令牌 / 短口令**：要保护就开「访问令牌」（16 位，可选，默认关），不做
  4 位数字那种折中——局域网里几秒就能枚举完，不是认证。
- **不做文件夹**：一期只放文件，文件夹让用户自己压成 zip。这一条同时去掉目录递归、
  流式 zip、文件数上限与「路径是文件还是目录」的分支。
- 不做目录树浏览、不做 HTTPS、不做 P2P、不做公网穿透。
- 不做多会话 / 有效期 / 一次性链接：**链接长期有效**，不搞轮换。
- 不做速记 / 采集历史的直接挂载。

## 1. 已确认的决策

| # | 决策 | 结论 |
|---|---|---|
| 1 | 形态 | 像 LocalSend，但**只有一端装**：本机跑服务，其他设备用浏览器；共享区持久保留，不是一次性会话 |
| 2 | 链接 | **固定**：默认 `http://<ip>:<端口>/`；开启令牌后 `http://<ip>:<端口>/s/<令牌>`，令牌只生成一次、不轮换 |
| 3 | 内容组织 | 本机发出去 = `items.json` 清单 + `files/`（只有剪贴板/截图落盘）；对方发来的 = `inbox/` 目录 |
| 4 | 服务 | 可开可关，记住上次状态；窗口只是管理界面 |
| 5 | 方向 | 双向：电脑发出去、对方发回来；浏览器端是一条收发流 |
| 6 | 协议 | 明文 HTTP，Kestrel 绑 `0.0.0.0`；子网校验兜底 |
| 7 | 端口 | 默认 **18767**（避开 MCP 的 18766、Quicker 的 18765），可改 |
| 8 | 内容来源 | 剪贴板文字 / 图片 / 文件、选择文件（可多选）、截图并共享 |
| 9 | 浏览器兼容 | 纯 HTML/CSS/JS，不依赖 WebRTC / Notification / Service Worker |
| 10 | 文字 | 对方发来的进剪贴板 + 落 `inbox/文字 <时间>.txt`；本机发的记进清单，两边都能看到 |
| 11 | 设备名 | 浏览器首次打开起个名字（存 `localStorage`），随请求头发给电脑端显示 |

第 2 条的令牌默认关：只有用户明确打开才启用；关掉时地址回到根路径，**令牌值保留**，再打开还是同一个地址。

## 2. 数据模型

### 2.1 配置：`configs/settings.json` 的 `Share` 段

只有 6 个字段，照 `Record` 的做法进 `settings` 域：`AppConfig.Share` +
`ConfigBundle.ToSettings` / `LoadCore` + `LTools.example.json`，共四处。

```
ShareOptions
  Port         = 18767
  Running      = false     // 上次是否在共享；启动时按它恢复
  AllowInbound = true
  MaxUploadMb  = 200       // 单文件上限；总量硬编码 1 GB
  RequireToken = false     // 访问令牌开关；打开后地址变成 /s/<令牌>
  Token        = ""        // 首次打开开关时生成 16 位十六进制；关掉不清空
```

- **没有会话、没有有效期**：链接长期有效，内容长期保留，用户手动删。
- **令牌只生成一次**：关掉开关不清空 `Token`，再打开还是同一个地址；只有「重置令牌」
  才换新的，旧地址立刻 401。换地址的另一条路是「换端口」。
- `Running` 持久化：昨天开着，今天开机还开着；不想共享就关掉并记住。

### 2.2 落盘：清单 + 目录

```
share/
  items.json           // 本机发出去的清单
  files/<文件>         // 没有原文件的（剪贴板、截图）才落这里
  inbox/<文件>         // 对方发来的（都是上传的副本）
  inbox/.partial/      // 未完成的分片上传，24 小时未动就清掉
```

**发送 = 记一个路径，不复制。**

| 来源 | 动作 |
|---|---|
| 选择文件 / 拖入 / 剪贴板文件 | `items.json` 加一条，`path` 指向原文件（**零复制、跨盘也成立**） |
| 剪贴板文字 | 写 `files/文字 <时间>.txt`，清单记 `copied = true` |
| 剪贴板图片 | 存 `files/图片 <时间>.png`（同上） |
| 截图并共享 | 存 `files/截图 <时间>.png`（同上） |

- 大文件（视频、安装包）加进来是**瞬间的**，磁盘上仍然只有那一份；跨盘也一样。
- `items.json` 每条：`{ id, name, path, size, mime, addedAt, copied }`。
- 原文件被移动 / 删除 / 改名 → 列表标「已失效」，下载 404，可一键移除。
- 重名不冲突：`name` 只是显示名，`path` 各自独立。
- 删除一条：`copied = false` 只从清单移除，原文件不动；`copied = true` 连
  `files/` 里的那一份一起删。
- **接收 = 落 `inbox/`**：对方上传的文件本来就没有「原文件」，直接写一份。
- `share/` 加进 `.gitignore`，不进备份。
- **不做「挂载整个目录」**：想共享 `D:\xxx` 里的东西就把它加进来，挂载目录树是
  另一种形态，一期不做。

## 3. 电脑端窗口

`Views/ShareWindow.xaml(.cs)`，`views:WindowSizing.Mode="Main"`（默认 75% 工作区，
最小 720×460），左栏 `*`、右栏固定 260。

### 3.1 标题栏

- 项目统一的 `controls:TitleBar`（拖动 / 双击最大化 / 最小化 / 关闭都由它处理，不需要自己写
  `DragMove`，也不要把按钮放进 `WindowChrome` 的 `CaptionHeight` 区域——那里收不到点击）。
- 窗口右上角只有系统窗口按钮；「共享 / 停止」与状态点在右栏顶部。

### 3.2 左栏（一屏聊天式收发）

- 顶部：`发出去的 N 项`。
- 内容行分两种（`ShareRowSelector` 按 `IsText` 选模板）：
  - **文字 = 正文卡片（方案 B）**：第一行摘要 `文字 · 20:11 · 62 B`，第二块是正文开头
    （最多两行，`MaxHeight` 38，超出由 `PreviewOf` 先截到 160 字 + `…`）；
    正文按「路径 + 修改时间 + 大小」缓存，1 秒轮询不反复读盘。双击看全文。
  - **文件 / 图片 = 单行**：26×26 色块（图片「图」、文件用扩展名）+ 名称（单行省略 + ToolTip）+
    `文件 · 12 B · 原地 / 副本`；原文件不在了就标红 `已失效`。**最新一条在最上面。**
- 行内常驻**文字按钮**（`ShareActionBtn` / `ShareRowBtn`，`CommandParameter` 认行，不收进菜单）：
  - 第一个：文字 → `复制`（整篇进剪贴板，超过 4 MB 提示用「查看」）；其它 → `打开文件`（默认程序打开）；
  - 第二个：文字 → `查看`（只读文本窗口看全文）；发出去的文件 → `复制路径`；
  - 收到的内容多一个 `另存为`；
  - 最后一个：`✕` 移除 / 删除（`DangerBrush`，移除只从清单去掉、不删原文件）。
  **双击整行**同样可用（文字打开只读文本窗口，其它定位文件），点在按钮上不会触发双击。
- 分区 `收到的 N`：对方发来的文件，行上标 `收到 · 1.2 MB`。
- 空态：`还没有内容` + 一句怎么发（输入框回车 / 取剪贴板 / 拖进来）。
- 列表 1 秒轮询一次（也可以直接在资源管理器里往目录丢文件，清单是唯一来源）。

### 3.2.1 发送区（左栏底部，不横跨右栏）

- 跟着内容流走：`DockPanel.Dock="Bottom"` 在左栏里，右栏是完整的一列。
- 一个圆角输入框（多行、自动换行、最高 140，聚焦时边框变深），**输入框内右侧两个图标按钮**：
  - 剪贴板（`E77F`）：读剪贴板里的**文件 → 图片 → 文字**（按这个优先顺序），直接进共享区；
  - 加号（`E710`）：选择文件（可多选）。
- 输入框右边是「发送」（`BtnPrimary`），输入为空时置灰。**回车发送、Shift+回车换行**
  （输入法组字时的回车不算）。
- 发出去的文字 = 一条 `文字 <时间>.txt`（`copied = true`），发送后输入框清空、焦点留在框里。
- 整窗接受拖放：**拖进来的文件原地记路径（不复制）**，同一个文件拖两次只留一条；
  **文字落进输入框**（可以改完再回车）、**图片存 `files/` 副本**。拖不认识的东西显示禁止光标。
- **拖放成立的前提是「窗口进程没提权」**：主程序是 `requireAdministrator`，UIPI 会拦住
  「中完整性 → 高完整性」的拖放（`Views/FileDropBridge.cs` 里把 `WM_DROPFILES` /
  `WM_COPYDATA` / `WM_COPYGLOBALDATA` / `WM_NCHITTEST` 都放行了、`WS_EX_ACCEPTFILES` 也设了，
  实测 Explorer 仍然不发）。所以**共享窗口跑在独立的普通权限进程 `ShareHost.exe` 里**（见 §2.1），
  拖放走正常 OLE，文件 / 图片 / 文字都能拖进来。在主程序进程里直接 `new ShareWindow()`
  （只有冒烟会这么做）时收不到拖放，这是预期。
- **参考实现（Quicker，2026-11-23 用 REA 看了安装目录的 shipped binary）**：
  - `Quicker.exe` 的清单是 `<requestedExecutionLevel level="asInvoker" uiAccess="true" />`，
    旁边就写着注释「uiAccess: bypass UIPI for SendInput/overlay/automation on elevated windows;
    requires signed install under Program Files」。**它的界面进程本来就是普通权限**，
    所以 Explorer 把文件拖进面板走的是正常 OLE，从来不需要绕过 UIPI；
    提权是「按动作需要」另起提权进程（`runAsAdmin` 参数、`IsElevated`、提权 agent）。
  - 另外它还自带一套原生文件落点：`[NativeFileDrop]` 日志（`已创建 {0}/{1} 个动作`、
    `未命中动作区`、`落点拒绝`）、`RegisterDragDrop` / `RevokeDragDrop`（自定义 `IDropTarget`）、
    `DragAcceptFiles` + `DragQueryFileW` / `DragFinish` + `WM_DROPFILES`、
    `ChangeWindowMessageFilterEx(WM_DROPFILES / WM_COPYGLOBALDATA)`，并读拖放来源的完整性级别。
    这是为了「在面板任意位置算落点、按落点建动作」，不是绕过 UIPI 的银弹。
  - LTools 用的是同一个思路的缩小版：**界面普通权限、提权留在主程序**，范围只有共享窗口。
    `uiAccess` 那条路走不了——它要求 exe 有代码签名、装在 Program Files 下，而 LTools 是免安装便携版。
- 粘贴：输入框里 Ctrl+V 的纯文字是普通粘贴（改完再回车）；图片 / 文件直接被收进共享区，
  不往输入框里塞文件名。焦点不在输入框时 Ctrl+V 也一样：图片 / 文件进共享区，文字填进输入框。

### 3.3 右栏

- 顶部：状态点 + `共享中 · 192.168.1.7:18767` / `已关闭` / `启动失败：<原因>`，
  下面就是「开始共享 / 停止共享」（`BtnPrimary`）——这一对是全窗口唯一的开关，
  标题栏只有系统窗口按钮。
- 二维码 184×184，白底；**可切换**：默认用第一条地址，点二维码换下一条、点某条地址行就用那一条
  （选中的行是一张白底卡片 + 深色描边，下面写着 `扫码打开 · 第 1/2 条（WLAN）· 点这里换一条`）。
  地址变了才重新生成（没有局域网地址时留空并写一行原因）。
- 共享地址 **一块一网卡，全部列出来**（服务绑 `0.0.0.0`，手机连 Wi-Fi、电脑插网线时两块网卡各自成网）：
  每行 `http://<ip>:<port>/`（启用令牌后 `<地址>/s/<令牌>`）+ 行尾「复制」；一条都没有时写一行原因。
  二维码只画第一条（主地址）；局域网判定也认全部网卡（`LanAddress.Candidates` → `ShareServer.Endpoints`）。
- `需要访问令牌` 开关（默认关）：
  - 打开时若 `Token` 为空就生成一个，地址与二维码立刻切换；
  - 关掉回到根路径，**令牌值保留**，再打开还是同一个地址；
  - 打开时下面多一行「重置令牌…」（要确认一次），旧地址立刻失效。
- `允许对方发来内容` 开关（默认开）；关掉时浏览器发送区变灰并提示「电脑已暂停接收」。
- 最近连接：`最近：小明的 iPhone · 3 秒前`（没有就写「还没有设备连接」）。
- **设置项全部平铺、就地改**（原来藏在「更多…」菜单里，端口 / 上限还要弹 `InputDialog`）：
  `端口 [18767]` / `上传上限 MB [64]` 是输入框（回车或失焦生效，Esc 还原，填错就地退回原值 + 红字提示），
  下面 `共享目录 share/ 打开`。改端口会重启服务并立刻写回 `configs/settings.json`。

### 3.4 没有的东西

没有倒计时、没有「延长」、没有「会话已结束」、没有「重新开始」。
**关窗不停止共享**，关程序才停；下次启动按 `Running` 恢复。
输入框下方一行灰字说明：`回车发送 · Shift+回车换行 · 文件可拖进来，文字 / 图片也可以粘贴`。

## 4. 浏览器端

单文件 `Assets/Share/index.html`（内嵌 CSS/JS，`Content Include="Assets\Share\**"`，
照 `Assets/Ocr` 的写法），不引外部 CDN。

### 4.1 一屏双向流，不是目录树

打开就是一屏「收发记录」，像聊天窗口，不是文件管理器：

- 上半区 **电脑发来的**：`items.json` 里的内容，按时间倒序；失效的标「已失效」。
- 下半区 **收到的**：`share/inbox/` 的内容，标「来自 <设备名>」；本页发过的再标
  「你发的」（`localStorage` 记文件名，换设备或清缓存会丢）。
- 底部常驻发送条：文字输入 + 选文件 / 拍照 + 发送。

每条内容一张卡：

| 类型 | 卡片 |
|---|---|
| 文字（`.txt`） | 正文最多 12 行 + 「展开」，右上「复制」 |
| 图片 | 缩略图（`object-fit` + `loading="lazy"`，**不生成缩略图**），点击全屏，右上「下载」 |
| 其他文件 | 扩展名图标 + 名字 + 大小 + 「下载」 |

### 4.2 发送

- 文字：输入 → 发送 → 电脑剪贴板 + 落 `inbox/文字 <时间>.txt`，卡片出现在
  「收到的」顶部并标「你发的」。
- 文件：选择 / 拖入 / 拍照 → 分片上传（8 MB 一段，`XMLHttpRequest` 有进度）→ 落 `inbox/`。
- 上传中显示百分比 + 速度 + 「取消」；失败可重试，不刷新整页。
- 中断后重新打开：顶部提示「上次有文件没传完（会议录像.mp4，已传 1.2 GB）」，
  重新选同一个文件就从断点继续。
- 电脑端同时弹 toast「收到 1 项来自 <设备名>」；窗口没开时用托盘气泡。

### 4.3 设备名

- 首次打开弹一次「你叫什么名字」，默认按 UA 粗判（`iPhone` / `Android` / `Windows`），
  存 `localStorage`，之后随 `X-Share-Device` 发送。
- 电脑端窗口与页面里的「你发去的」都按这个名字显示来源。

### 4.4 布局

- 宽屏（≥ 720px）：左流、右固定发送栏。
- 窄屏（< 720px）：单栏，发送条固定在底部，键盘弹起时不遮输入框。

### 4.5 兼容与约束

- 轮询 `/api/state` 每 2 秒（离开标签页自动停）。
- `navigator.clipboard` 不可用（`http` 非安全上下文）时用 `textarea + execCommand` 兜底。
- 文本一律 `textContent` 渲染，不拼 HTML。
- 不依赖 WebRTC / Notification / Service Worker。
- 上传失败 / 被暂停接收时就地提示，不清空已输入的文字。

## 5. HTTP 接口

令牌关闭时接口不带任何凭证；打开后页面地址变成 `/s/<令牌>`，后续接口用 `?k=`：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` 或 `/s/{令牌}` | 浏览器页面；`RequireToken` 为真时只认后者 |
| GET | `/api/state` | 是否允许接收 / 文件清单（含小文本内容）/ 最近连接 |
| GET | `/api/raw/item/{id}` | 下载或预览本机发出去的一条（支持 `Range`） |
| GET | `/api/raw/inbox/{name}` | 下载对方发来的一条（支持 `Range`） |
| POST | `/api/text` | 文字（`application/json`）：进剪贴板 + 落 `inbox/文字 <时间>.txt` |
| POST | `/api/upload/init` | 开始或继续一次上传：`{ name, size, sha256, uploadId }` → `{ uploadId, offset }` |
| POST | `/api/upload/append?uploadId=&offset=` | 追加一段（二进制）；`offset` 必须等于已收字节数，否则 `409` |
| POST | `/api/upload/finish?uploadId=` | 校验大小与 `sha256`，移到 `inbox/` |
| GET | `/api/upload/pending` | 未完成的上传，页面加载时据此提示「重新选同一个文件可继续」 |

- 令牌校验：`?k=`、`Authorization: Bearer`、`X-Share-Token` 三选一，定长比较
  （同 `AiSettings.TokenEquals`）；`RequireToken` 为假时整段跳过。
- 令牌开启时访问 `/` **不返回内容**，只回一个「此共享需要令牌，请用完整地址或扫码」
  的提示页——不泄露文件清单。
- 设备名走 `X-Share-Device`，缺省按 UA 粗判。
- **完整性**（照 LocalSend 的 `prepare-upload` / `422`）：上传可带 `sha256`，
  收完核对，不匹配 `422` 并删掉半截文件。
- 回执统一 `{ ok, ... }` / `{ ok: false, error }`。
- 错误码：`401` 令牌不对、`403` 来源不在本机子网 / 已暂停接收、`404` 文件不存在、
  `409` 断点位置不对、`413` 超限、`422` 校验不匹配、`429` 请求太频繁。

### 5.1 断点续传

**下载**：`/api/raw/item/{id}` 与 `/api/raw/inbox/{name}` 都返回 `Accept-Ranges: bytes`，
支持 `Range` 与 `206`。浏览器自己能续传的（Chrome / Edge 同一次下载）就续，不能的
从头发——服务端已经把能力给出来了。

**上传**：浏览器没有「续传上一次上传」的原生能力，所以自己做**追加式分片**：

1. 页面按 `File.slice()` 每次发 8 MB，`POST /api/upload/append?uploadId=&offset=`。
2. 服务端写在 `inbox/.partial/<uploadId>.part`，每段校验 `offset` 等于当前长度
   （不匹配回 `409`，防止重复写或乱序）。
3. 全部发完 `POST /api/upload/finish`，校验 `size` 与 `sha256`，移到 `inbox/`。
4. 中断后重新打开页面：`GET /api/upload/pending` 给出未完成的条目；用户重新选
   **同一个文件**，`uploadId`（`name + size + lastModified` 的哈希）对得上，从
   `offset` 继续。

**边界**：浏览器安全策略不允许页面记住上次选的文件，所以「续传」的准确含义是
「重新选同一个文件后从断点继续」，不是全自动。`.partial/` 超过 24 小时未动会被清掉。

## 6. 生命周期

窗口与服务都跑在**独立进程 `ShareHost.exe`**（asInvoker）里，主程序只下指令：

| 谁 | 做什么 |
|---|---|
| 主程序启动 | `Share.Running == true` → 写 `run` 意图 + 拉起助手（窗口隐藏） |
| 托盘 / 内置功能 `ltools.share` | `ShareHelper.Open()` → 写 `show` 意图（已在跑就只写意图，400ms 内唤起） |
| 窗口「停止共享」 | 助手自己 `ShareServer.Apply(Running=false)`，写回配置 |
| 关窗（X） | 服务还在跑 → 只隐藏窗口；服务已停 → 助手进程一起退出 |
| 主程序退出 | `ShareHelper.Stop()` → 写 `stop` 意图，助手停服务并退出（不等它，进程结束自然释放端口） |

**进程间只靠两样东西**：

- 命名互斥体 `Local\LToolsShareHost`：主程序用它判断「助手在不在跑」；
- `share/host.intent`：内容 `run` / `show` / `stop`，助手每 400ms 读一次、执行完删掉。

**为什么用文件而不是命令行**：主程序提权，直接 `CreateProcess` 出来的子进程会继承高完整性令牌
（那样窗口照样收不到拖放）。要拿到普通权限的子进程，只能借 Explorer 的身份——但它是
**复制 Explorer 的令牌再 `CreateProcessWithTokenW`**（`Native/ShellToken.cs`），
不是 `explorer.exe <exe>`：后者会顺手把资源管理器窗口叫到前台（用户报过「第一次打开共享，
资源管理器跳出来了」），`Shell.Application.ShellExecute` 也不行（在提权进程里那是进程内对象，
子进程照样提权）。复制令牌只要 `SeImpersonate`（管理员自带），也不碰资源管理器的窗口，
所以进程之间仍然只用意图文件、**不需要命令行参数**。

1. 助手启动：`ConfigStore.UsePathOnly()`（只记配置路径，**不扫动作目录、不修引用、不播种快捷键**）
   → `AppLog.Configure()`（与主程序同一份日志配置）→ 读 `Share` 段 → `ShareServer.Apply()`。
2. 窗口 / 托盘：「共享 / 停止」只切监听，写回 `Running`；内容不动、地址不动。
3. 添加 / 删除内容：本机发出去的改 `items.json`（外加 `files/`），对方发来的改 `inbox/`。
4. 退出：`Stop()` 只把 `StopAsync` / `DisposeAsync` 排到后台任务，**UI 线程绝不等**
   （照 `McpServer` 的教训，否则退出卡死托盘）。

打包：`ShareHost.exe` 必须和 `LTools.exe` 在**同一个目录**（它按自己的 exe 位置算数据根）。
`dotnet publish LTools.csproj …` 会自动把助手也发出来（`PublishShareHost` target）；开发构建
由 `ShareHost.csproj` 的 `CopyToAppFolder` 拷进主程序输出目录。

## 7. 线程模型

| 在哪 | 做什么 | 不许做什么 |
|---|---|---|
| Kestrel 请求线程 | 读清单 / 目录、读文件流、`AppLog` | 碰 WPF、等 UI 线程 |
| 文字接收 | `StaRunner.Run(() => NativeClipboard.SetText(...), 3000)` | 直接调 OLE 剪贴板 |
| 添加内容（UI 触发） | 先在 `Task.Run` 里写清单或落盘，完成后 `Ui.Post` 刷新 | 在 UI 线程上做文件 IO |
| UI 刷新 | `Ui.Post`（只排队不等待） | 从请求线程 `Dispatcher.Invoke` |

目录列举本身无共享状态（每次现读），不需要锁。

## 8. 安全边界

**令牌是可选项，不是主防线**

`RequireToken` 默认关。16 位令牌能把地址变得没法念，换来的是「同网段的人猜不到」；
4 位短口令则几秒就能枚举完，不算认证。所以只提供「完整的 16 位令牌」这一种形态，
不做短码。无论开关是否打开，真正的保护都来自下面四条：

1. **默认关闭**：`Running = false`，不主动开就完全不监听。
2. **只接受本机当前网卡的同一子网**：用选中网卡的 `PrefixLength` 算子网，
   `RemoteIpAddress` 不在里面就 403。不是「任何私有网段」——连了公司 VPN 时，
   公司内网的其他机器也进不来。
3. **浏览器只读**：能看、能下载、能发来，但删不掉任何东西；删除只有电脑端能做。
4. **只读清单与 inbox**：发送项只能按 `items.json` 里的 `id` 取，路径在加入时
   校验过（绝对路径、存在、是文件）；接收项只认 `inbox/` 目录 + 校验过的文件名。
   不提供任何「按路径取文件」的入口。

其余：

- **文件名清洗**：去掉 `<>:"/\|?*` 与控制字符，限长 120，避开 `CON` / `PRN` /
  `AUX` / `NUL` / `COM1`…。
- **上传限制**：单文件 `MaxUploadMb`，总量 1 GB；不自动打开、不自动执行。
- **限流**：同一来源 IP 每分钟最多 120 次请求、10 次上传，超出 `429`——照 LocalSend
  的做法，给「可选令牌」和上传口留一道防脚本刷的闸。
- **不写敏感日志**：`AppLog` 只记状态与计数，不记文件内容。

**明确接受的风险**：令牌关闭时，同一个 Wi-Fi 下的人知道 IP、扫到端口就能打开共享区；
打开令牌后，猜不到 `/s/<令牌>` 就进不来。共享区里的内容按「同一间屋子里的人能看到」
对待。想要「只给特定的人看」，用令牌 + 在路由器上绑固定 IP；明文 HTTP 本身不提供保密。

## 9. 网络与防火墙

- `LanAddress.Candidates()`：`NetworkInterface.GetAllNetworkInterfaces()`，口径照 **LocalSend**
  （Dart `NetworkInterface.list`）——**除回环与 169.254 链接本地外，所有 IPv4 地址全部列出**，
  不看 `OperationalStatus`、不按网卡名过滤虚拟网卡。装了 VMware / Hyper-V / Tailscale / 代理 TUN
  时每块网卡都可能是一部手机真正能连到的入口，漏列就是「手机连不上」。
  实现：`LanAddress.IsListable(ip)`（IPv4、非 127/8、非 169.254/16）。
- 排序只影响「二维码默认画哪一条」：有默认网关的在前，再按 `192.168.*` > `10.*` > 其它。
- 每一块地址都出现在右栏列表里，点哪条就用哪条画二维码（也能点二维码轮换）；**入站校验认全部网卡**
  （`ShareServer.Endpoints` + `IsLocal` 逐块 `Contains`），不再只认第一块。
- 防火墙：**还没自动加规则**（见 §12 的遗留项）。第一次开共享时 Windows 可能弹「允许访问」，
  允许一次即可；被拦掉时状态是「启动失败 / 手机打不开」，加规则需要提权，Debug 版只能手工放行。
- 没有局域网 IP（只有回环）：提示「当前没有局域网连接」，不生成二维码。

## 14. 已知限制

- **IP 可能变**：地址的路径不变，但 `192.168.x.x` 由路由器 DHCP 分配。换了网络或
  租约到期后，旧地址失效；窗口会显示新地址，重新扫码即可。想彻底固定，在路由器上
  给这台电脑绑定固定 IP。
- **同网段可见**：令牌关闭时，同一 Wi-Fi 下知道 IP 的人能打开共享区；打开令牌后要
  知道 `/s/<令牌>` 才能进。靠「默认关闭 + 同一子网 + 浏览器只读」收窄，不做假认证。
- 明文 HTTP：同网段有嗅探能力的设备能看到内容。
- 公共 Wi-Fi 开「客户端隔离」时设备互相连不上，属于网络侧限制，程序只能提示。
- 大图不生成缩略图，几十张 4K 截图时手机首次加载会慢；局域网带宽下可接受。
- **原文件移动 / 删除会失效**：发送是记路径，不复制。原文件被移动、改名或删除后，
  这一条标「已失效」；重新添加即可。
- **清单存的是绝对路径**：换电脑、改盘符或把共享目录搬到别处后，清单里的条目
  全部失效，需要重新添加。
- **上传续传要重新选文件**：浏览器不允许页面记住上次选的文件，断点续传的前提是
  重新选中同一个文件（同名、同大小、同修改时间）。
- 大文件下载走流式，不支持断点的浏览器会从头重下。
- **防火墙规则没有自动添加**：首次监听时由 Windows 弹「是否允许访问」，点允许即可。
- **拖放只在助手进程里成立**：窗口跑在 `ShareHost.exe`（普通权限）时拖放正常；如果哪天有人
  把它改回主程序进程里开窗（或以管理员身份直接启动 `ShareHost.exe`），UIPI 会拦掉拖放
  （替代：`Ctrl+C` + `Ctrl+V` 或剪贴板图标）。主程序拉起助手固定走 `Native/ShellToken`
  （复制 Explorer 的令牌再 `CreateProcessWithTokenW`），**别改成直接 `CreateProcess`**
  （子进程继承高完整性令牌），**也别改回 `explorer.exe <exe>`**（那样会把资源管理器窗口
  叫到前台）；`ShellToken` 起不来时才兜底退到 `explorer.exe`。
- **第一次打开共享窗口可能不拿键盘焦点**：助手是后台进程，Windows 的前台锁不给它抢焦点的权利，
  所以窗口会**出现在最前面**（借置顶带抬一次再放下），但键盘焦点可能还留在原来的程序里——
  点一下窗口就能输入。这是系统规则，不是窗口没打开。
- **「截图并共享」还没接进输入框的图标**：一期先支持输入框文字、剪贴板、选择文件、拖放与粘贴。
